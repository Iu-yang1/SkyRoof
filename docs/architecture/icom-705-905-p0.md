# Icom IC-705 / IC-905 — P0 protocol baseline

**Status:** protocol foundation only; no IC-705 / IC-905 CAT transmit or network scope feature is enabled by this change.

## Model and transport candidates

| Model | Default CI-V address | Scope receivers | Transport candidates | Verified in this P0 PR |
| --- | --- | ---: | --- | --- |
| IC-9700 | `0xA2` | MAIN/SUB (2) | USB / Ethernet | Existing behavior preserved; CI suite regression required |
| IC-705 | `0xA4` | 1 | USB / WLAN | Model profile, BCD and passive response parsing only |
| IC-905 | `0xAC` | 1 | USB / Ethernet | Model profile, 5/6-byte BCD and passive response parsing only |

The addresses are **defaults, not model identifiers**. An operator may change a CI-V address, and multiple devices can use the same address. Any runtime identification must corroborate the model with a separately obtained radio name or capabilities response. This P0 implementation does not send identification, PTT, or tuning commands.

## Frequency encoding

- IC-705 / IC-9700 standard CI-V frequency: little-endian packed BCD, five bytes.
- IC-905 below 10 GHz: five bytes. At 10 GHz: six bytes.
- Values are stored as `long` Hz; invalid BCD digits, unsupported byte lengths, negative operating frequencies and overflow are rejected.
- Signed offsets and other specialized command payloads must not be routed into the unsigned operating-frequency decoder.
- `IcomScopeAssembler` is still the IC-9700 five-byte implementation; adapting IC-905 `27 00` scope headers is a **P2 task**. Do not advertise IC-905 scope support yet.

## Legacy Direct LAN protection

The existing `IcomLanDirectSession` configures an IC-9700-specific `27` series scope output. Its capability response now has to identify **IC-9700 by name** before the legacy setup sends the CI-V stream request or scope-output writes. Identified IC-705, IC-905, missing or unknown model names are rejected with an explicit unsupported-model diagnostic; this does not alter the working IC-9700 scope path.

## Tests and acceptance level

- `VE3NEA.Dsp.Tests/IcomRadioCompatibilityTests.cs`: default profiles, single/dual receiver flags, unknown and configurable addresses, 5-byte IC-9700 golden vector, 6-byte IC-905 10 GHz golden vector, invalid BCD, truncation/overflow and read-only response validation.
- Preexisting IC-9700 scope, CAT, CW, SSTV and audio tests remain part of the Windows CI.
- CI green means **protocol simulation and build acceptance**, not completed IC-705 or IC-905 physical integration.
- Hardware acceptance for P1–P3 requires separately recorded model, firmware, selected transport, frequency/mode/PTT and AF/IF/scope results. Previous IC-9700 field tests do not automatically qualify new models.
